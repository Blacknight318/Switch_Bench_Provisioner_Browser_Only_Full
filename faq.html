Switch Bench Provisioner FAQ

Browser-only Cisco IOS / IOS-XE bench-provisioning guidance.

← Return to the provisioner

What is this tool for?

It is a bench-only planning and browser-serial provisioning tool for supported Cisco Catalyst IOS / IOS-XE switches. Review generated configuration before applying it, and manually save the switch configuration only after validating the result.

Does the hosted demo upload my profile, key file, serial output, or credentials?

No. The application is static and processes files selected by you in the browser. It has no application API, upload endpoint, analytics request, or server-side serial service. Imported key-file content is encrypted in active-tab memory and is cleared on the documented clear, replacement, disconnect, unload, and inactivity events.

This protects against routine persistence and accidental exposure. Do not import real credentials into a browser or workstation you do not trust, and do not commit a real .env file to Git.

Where do I get the example files?

  • View .env.example on GitHub
  • View profile.distribution.example.json on GitHub

Copy each example locally. Use a private .env for site values and secrets; keep profile.distribution.example.json as the reusable sanitized template. Do not publish a site-specific profile unless it is reviewed and intentionally sanitized.

Which browser should I use for serial access?

Use Chromium or Microsoft Edge over HTTPS or http://localhost. Web Serial requires you to explicitly choose a serial device; the web page cannot silently open a serial port.

Will the tool update switch firmware?

No. Firmware updates are intentionally out of scope. Image transfer, image integrity, storage capacity, install/bundle mode, boot variables, compatibility, and rollback must be validated for the exact model and release before any write action.

Why does Apply require review and typed confirmation?

Serial configuration changes can affect a live device immediately. The tool requires a generated preview, explicit review acknowledgement, and a typed APPLY confirmation. It does not automatically run write memory or copy running-config startup-config.

What should I do if a generated command is rejected?

Stop the apply, preserve non-secret command/error evidence, and verify the exact IOS / IOS-XE model and release. Do not force a generic hardening command that the platform parser rejects. Correct or capability-gate the generator before retrying.
